# Job 1: baseline for 0.10 (Mac worker)

## Setup

- Commit measured: `2270076` (`origin/claude/0.10-faster-turns`: 0.9's code plus the measurement-jobs doc). Job 0 was done first: `npm ci`, then `bench --verify` was "same" for all four games (the warm-up).
- Machine: MacBook, Apple M2, 8 cores, 16 GB, on mains power (100 %). Node v24.10.0, npm 11.6.0, macOS Darwin 27.0.0.
- Date: 2026-11-10, about 22:20–22:35 CET.
- Every heavy run went through `~/.claude/bin/one-at-a-time --min-free-gb 2`, one at a time. The disk had only 3.5 GB free, so the default 8 GB would have waited for ever; `npm ci` and the runs used almost none of it.
- **The machine was not quiet.** Chrome (several processes, 12–17 % CPU at times), VS Code and the window server were running, and the load average was 1.3–2 before the runs. I did not close the user's apps. The spread between runs is small, so it did little harm.
- Worked in a separate git worktree (detached at `2270076`, its own `node_modules`), so the main checkout was not touched.
- Bench timings are the seconds the bench prints (one decimal), from `node scripts/.bench.mjs` after one `npm run bench` build. Three timed runs each, after the warm-up. `--year` and `--quiet` behave as the job describes: `--quiet` drops the phase table and leaves two lines.

## Unusual

- Noise between runs is small (at most 0.4 s on the 1750 game, 0.1–0.2 s elsewhere). The first 1750 run was the lowest, the third the highest (11.1 s), which may be the browser or other apps in the background.
- The 1750 head start ends at turn 356 rather than turn 409 (see above).
- No warnings, failures or crashes. `npm ci` printed only an npm update notice.
- `bench --verify`'s Caribbean line label "seed 2024, to 1700" is a label from the script, not the year played.
